## 必须改

### M1｜删掉「Record 2.5.4 specification self-checks」整步

**位置**：`.github/workflows/build-lckfb.yml` 第 57–65 行

```yaml
- name: Record 2.5.4 specification self-checks
  run: |
    git branch wip/2.5.4-baseline c19b11d      # 硬编码基线
    ...
    grep -q '^CONFIG_OTA_URL="http://47.117.142.184:8003/xiaozhi/ota/"$' sdkconfig
```

三个问题：

1. **硬编码 `c19b11d`**：基线一推进就失效。当前基线已是 `8c5858e`，再跑必错。
2. **在 CI 里造本地分支**：构建容器是干净环境，`git branch` 只为对齐审查视角，对产物零价值。
3. **它让整个 run 失败**：这次第 7 步 `exit 128`，导致第 8 步 Upload 被跳过——**固件编出来了但没传上来**。

自检输出也没进 artifact，删掉不影响任何交付物。自检本来就该在交付时由实现方贴进 PR，不该进流水线。

### M2｜`flash-args.txt` 的 version 不能写死

**位置**：同文件第 55 行 `version : 2.5.4`

下次改版本号必然忘改这里，产物参数表就和固件对不上。改成从源头取：

```bash
VER=$(grep -oE 'PROJECT_VER "[0-9.]+"' CMakeLists.txt | grep -oE '[0-9.]+')
```

### M3｜heredoc 结束符缩进，文件内容会带 10 个空格

**位置**：同文件第 47–56 行

`EOF` 前面有 10 个空格。`<<EOF` 的结束标记**必须顶格**，否则 bash 认为 heredoc 未结束，写出的每一行都带 10 空格前缀（本次没报错只是因为后面没有其他 shell 语句接续）。

改用 `printf` 拼，或把 `EOF` 顶格。

## 建议改

### S1｜`fetch-depth: 0` 跟着自检一起删

它只为 M1 那步服务。删掉自检后保留它，等于每次构建都多拉一份完整历史。

### S2｜T3 每次都开可写 NVS

`main/ota.cc`：`Settings settings("wifi", true)` 让**每次** OTA 检查都以可写方式打开命名空间，即使根本不需要清理。

当前功能正确，但可以只在 `IsLocalUrl(url)` 命中时才开写。属于优化，不阻塞。
